# worker-diag-flush — Data model

The worker owns no schema of its own. It consumes one Redis Stream and writes one Postgres table; both are owned by neighbouring components but inserts/reads through this worker are the bulk of the runtime traffic.

## Redis Stream — `diag:queue`

Owner: [`@squad/diag`](../../diag/README.md). Producer half writes via `XADD`; this worker consumes via `XREADGROUP`.

- Key: `diag:queue` (constant `DIAG_STREAM_KEY` exported from `@squad/shared-config`).
- Trim policy: producer-side `MAXLEN ~ 100000` (constant `DIAG_STREAM_MAXLEN`). At ~300 bytes/entry that bounds Redis memory at ~30 MiB.
- Field shape (one entry):

| Field | Required | Type | Notes |
|---|---:|---|---|
| `id` | yes | string (UUIDv7) | Generated by producer with `uuidv7()`. Primary-key half. |
| `ts` | yes | string (ISO 8601 with TZ) | Generated by producer with `new Date().toISOString()`. Primary-key half. |
| `component` | yes | string | Free-text — `api`, `worker-rcon`, `bridge`, etc. |
| `severity` | yes | string | One of `debug`, `info`, `warn`, `error`, `fatal` (CHECK enforced at INSERT). |
| `kind` | yes | string | Dotted-namespace event type, e.g. `server.start.requested`, `rcon.auth.failed`. |
| `server_id` | no | string (UUID) | Null when not server-scoped. |
| `actor_steam_id64` | no | string (digits) | Steam ID64 of the panel user that triggered the event, when applicable. Cast `::bigint` at INSERT. |
| `request_id` | no | string | Tracing id from `X-Request-Id` (api-side) or worker run id. |
| `message` | yes | string | Short human-readable summary. |
| `payload` | no | string (JSON) | Arbitrary structured detail. Defaults to `'{}'` if missing. Cast `::jsonb` at INSERT. |

Example entry as returned by `XREADGROUP`:

```
[
  '1750000000000-0',
  [
    'id', '019dbaa5-0000-7000-8000-000000000001',
    'ts', '2026-04-28T10:00:00Z',
    'component', 'api',
    'severity', 'info',
    'kind', 'server.start.requested',
    'request_id', 'req-abc',
    'message', 'manual',
    'payload', '{"server_id":"00000000-0000-0000-0000-000000000001"}',
  ]
]
```

## Consumer group — `diag-flush`

- Group name: `diag-flush` (`GROUP` constant in `src/index.ts`).
- Consumer name: `diag-flush-${process.pid}` (so multiple replicas of the worker each get a unique consumer; restart resets it because PID changes).
- Created on startup with `XGROUP CREATE diag:queue diag-flush $ MKSTREAM`. The `$` start id means the consumer group reads only entries `XADD`ed after group creation; entries written before the first ever startup are ignored. `BUSYGROUP` errors are swallowed so subsequent restarts are no-ops.
- `MKSTREAM` ensures the stream is created if no producer has yet written, so the worker can come up before the first emit.

## Postgres table — `diagnostic_events`

Owner: [`@squad/db`](../../db/README.md) (schema in [`packages/db/src/schema/diagnostic-events.ts`](../../../../packages/db/src/schema/diagnostic-events.ts), migration `0017_diagnostic_events.sql` introduced in commit `d68fb21`).

| Column | Type | Constraints |
|---|---|---|
| `id` | `uuid` | NOT NULL, PK part 1 |
| `ts` | `timestamp with time zone` | NOT NULL, PK part 2 |
| `component` | `text` | NOT NULL |
| `severity` | `text` | NOT NULL, CHECK `severity IN ('debug','info','warn','error','fatal')` |
| `kind` | `text` | NOT NULL |
| `server_id` | `uuid` | nullable, FK → `servers(id)` `ON DELETE SET NULL` |
| `actor_steam_id64` | `bigint` | nullable |
| `request_id` | `text` | nullable |
| `message` | `text` | NOT NULL |
| `payload` | `jsonb` | NOT NULL, default `'{}'::jsonb` |

Indexes:

- `diagnostic_events_pkey` — composite (`id`, `ts`); idempotency comes from `ON CONFLICT (id, ts) DO NOTHING` on this PK.
- `diagnostic_events_ts_idx` — `(ts)` for time-range scans.
- `diagnostic_events_server_ts_idx` — `(server_id, ts)` for per-server bundle queries.
- `diagnostic_events_kind_ts_idx` — `(component, severity, ts)` for severity-ranked queries.

## INSERT shape emitted by `flushBatch`

```sql
INSERT INTO diagnostic_events
  (id, ts, component, severity, kind, server_id, actor_steam_id64, request_id, message, payload)
VALUES
  ($1, $2::timestamptz, $3, $4, $5, $6::uuid, $7::bigint, $8, $9, $10::jsonb),
  ($11, $12::timestamptz, $13, $14, $15, $16::uuid, $17::bigint, $18, $19, $20::jsonb),
  ...
ON CONFLICT (id, ts) DO NOTHING;
```

The `::timestamptz`, `::uuid`, `::bigint`, `::jsonb` casts are explicit because `sql.unsafe` does not infer Postgres types from JS values — string-typed args are sent and the server casts.

## Idempotency

A re-delivered batch (worker died after INSERT but before `XACK`) hits the PK and is dropped silently by `ON CONFLICT (id, ts) DO NOTHING`. No duplicates land. No `XACK` was issued, so the entries are still pending — the next `XREADGROUP` redelivers them and the second iteration `XACK`s them.
