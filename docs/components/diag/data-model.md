# `diag` — data model

The package owns one piece of state: the wire shape of each entry written to the `diag:queue` Redis Stream. The Postgres `diagnostic_events` partitioned table is owned by the [`db`](../db/data-model.md) component (migration `0017_diagnostic_events.sql`); this page documents only what crosses the Redis boundary.

## Redis Stream `diag:queue`

- **Key:** `diag:queue` (constant `DIAG_STREAM_KEY` in `packages/diag/src/types.ts` and re-exported from `@squad/shared-config`).
- **Type:** Redis Stream (`XADD` / `XREADGROUP`).
- **Cap:** `MAXLEN ~ 100_000` enforced on every `XADD` (`DIAG_STREAM_MAXLEN`). Approximate (`~`) trimming is O(1); exact trimming would block. The cap is a safety net — under steady state the consumer (`worker-diag-flush`) keeps the stream short.
- **Entry id:** auto-generated by Redis on `XADD *` (millisecond timestamp + sequence, e.g. `1700000000000-0`). The consumer ACKs by id.
- **Group:** consumed under a single consumer group (`worker-diag-flush:flush`, defined by the consumer worker — out of scope here).

## Stream entry fields

Every `XADD` is a flat key/value pair list. The producer always emits these fields, in this order:

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | string (UUIDv7) | yes | Generated client-side via `uuid`'s `v7` export. The Postgres row uses this same id, so a stream entry that is partially flushed can be re-played without primary-key conflict (`INSERT … ON CONFLICT (id) DO NOTHING`). |
| `ts` | string (ISO 8601 UTC) | yes | `new Date().toISOString()` at emit time. Used by the consumer to assign the row to a daily partition. |
| `component` | string | yes | Producer name (e.g. `api`, `reconciler`, `worker-rcon`). |
| `severity` | `info \| warn \| error \| fatal` | yes | Surfaces in bundle §2 dedup grouping. |
| `kind` | string | yes | Dotted-path event kind (e.g. `server.start.requested`). |
| `server_id` | string (UUIDv7) | no | Omitted when undefined; consumer treats absence as SQL `NULL`. |
| `actor_steam_id64` | string | no | Omitted when undefined. |
| `request_id` | string | no | Omitted when undefined. |
| `message` | string | yes | Short human-readable line. |
| `payload` | string (JSON) | yes | `JSON.stringify(payload ?? {})`. Empty object when caller did not pass a payload. |

### Why field order matters

Redis Streams preserve insertion order of fields. The order above is the contract — the consumer parses by stepping over the array two entries at a time and indexing by name, but a misordered producer is still a buggy producer because diff/code-review tools rely on a stable order.

### Field naming

Producer (`DiagEvent`) uses camelCase (`serverId`, `actorSteamId64`, `requestId`) because that is the TypeScript convention. The Redis Stream and Postgres table use snake_case (`server_id`, `actor_steam_id64`, `request_id`) because that is the project convention for storage. The translation happens inside `emit()`.

## Example XADD argument list

```
XADD diag:queue MAXLEN ~ 100000 *
  id 019dbaa5-0000-7000-8000-000000000000
  ts 2026-04-28T12:00:00.000Z
  component api
  severity info
  kind server.start.requested
  server_id 019dbaa5-0000-7000-8000-aaaaaaaaaaaa
  actor_steam_id64 76561198000000000
  request_id req-abc-123
  message manual start via REST
  payload {"reason":"manual"}
```

## Postgres mirror — out of scope here

The persisted row lives in the `diagnostic_events` partitioned table, owned by [`db`](../db/data-model.md). Schema reference (from migration `0017_diagnostic_events.sql`):

```sql
CREATE TABLE diagnostic_events (
  id            uuid PRIMARY KEY,
  ts            timestamptz NOT NULL,
  component     text NOT NULL,
  severity      text NOT NULL,
  kind          text NOT NULL,
  server_id     uuid NULL,
  actor_steam_id64 text NULL,
  request_id    text NULL,
  message       text NOT NULL,
  payload       jsonb NOT NULL DEFAULT '{}'::jsonb
) PARTITION BY RANGE (ts);
```

`UPDATE` and `DELETE` are explicitly allowed on this table (unlike `audit_log`) so the wipe endpoint can `TRUNCATE` and the partition rotator can drop daily partitions older than 24h.
